# 本地大模型部署 · 验收记录（Ollama + ChatBox）

> 2026-11-20 · 第一列「基于Ollama+ChatBox实现ChatBot ★★」
> 验收标准（计划 4.2 部署类）：**跑通 + 截图 + 一页配置笔记**
> 数据来源：本机实测（2026-11-20 采集），不是抄文档。

## 一、一句话结论

RTX 5060 Laptop（8 GB 显存）跑 `qwen2.5:7b`（7.6B 参数 / Q4_K_M 量化 / 4.68 GB），
**100% 在 GPU 上**，实测生成 **47.7 tok/s**，显存占用 6.0 GB。

![ChatBox 连接本地 Ollama](img/chatbox-ollama.png)

## 二、环境

| 项 | 值 |
|---|---|
| GPU / 显存 | NVIDIA GeForce RTX 5060 Laptop GPU / **8151 MiB**（驱动 592.00） |
| 操作系统 | Windows 11（内核版本 10.0.26200） |
| Ollama 版本 | **0.5.7** |
| 模型 | `qwen2.5:7b` **4.68 GB**（params 7.6B / quant Q4_K_M / ctx 32768） |
| 其他已装模型 | `deepseek-r1:1.5b` 1.12 GB、`qwen2:0.5b` 0.35 GB |
| 接口地址 | `http://127.0.0.1:11434` |

## 三、能复现的最小步骤

1. 安装 **Ollama 0.5.7**（Windows 安装包），装完先跑 `ollama --version` 自检
2. 拉模型：`ollama pull qwen2.5:7b`
3. ChatBox 里填：API 地址 `http://127.0.0.1:11434`，模型选 `qwen2.5:7b`
4. 验证：发一句「你好」→ 看到回复；再跑 `ollama ps` → 应有 `100% GPU`

> 模型名必须和 `ollama list` 里显示的**完全一致**（`qwen2.5:7b` 不是 `Qwen2.5-7B`）。

## 四、实测性能

| 指标 | 数值 | 说明 |
|---|---|---|
| 生成速度 | **47.7 tok/s** | 每秒约 48 个字，比人读得快 |
| 提示处理 | 243 tok/s | 你发过去的上下文处理速度 |
| 显存占用 | **6.0 GB** | 权重 4.68 GB + 约 1.3 GB 上下文缓存 |

**为什么 8 GB 能跑 7.6B**：权重量化到 Q4（每参数约 4~5 bit），
`7.6B × 2 字节 ≈ 15.2 GB` 装不下，压到 4.68 GB 就装得下了。**这是量化的直接价值。**

## 五、踩过的坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 第一次提问卡住几秒没反应 | 模型要从硬盘加载进显存 | 等一次就好；`ollama ps` 的 UNTIL 显示闲置几分钟后会卸载，下次再加载 |
| 只跑 7B 就吃掉 6.0 GB，8 GB 卡几乎满 | 权重 4.68 GB + 上下文缓存 1.3 GB | 想跑 14B 必须换更大显存的卡——参数量直接决定硬件门槛 |
| 地址填错连不上 | ChatBox 选 Ollama 类型时填 `http://127.0.0.1:11434`；若选 OpenAI 兼容类型才需要 `/v1` | 两种类型别混用 |

## 六、怎么确认它真的在跑 GPU

```powershell
ollama ps
```

看 `PROCESSOR` 列：

```
NAME          ID              SIZE      PROCESSOR    UNTIL
qwen2.5:7b    845dbda0ea48    6.0 GB    100% GPU     4 minutes from now
```

- 显示 `100% GPU` → 显卡在干活
- 显示 `100% CPU` → 掉到 CPU 上了，速度会差十倍以上（通常是显存不够装不下）

再交叉验证：开着对话跑 `nvidia-smi`，显存占用应涨到约 6 GB。

> `UNTIL 4 minutes from now` 是 Ollama 的默认保活时间：闲置超时就把模型从显存卸载，
> 把卡腾出来。所以隔一阵再问，第一次会重新加载。
