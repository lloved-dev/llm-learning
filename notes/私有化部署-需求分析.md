# 私有化大模型部署 · 需求分析

> 2026-11-17 · 第一列「私有化大模型部署 ★★」理论部分之一
> 验收标准：200 字自己的话 + 3 个面试问答。来源：黑马课程「需求分析」+ 自测问答。

## 一、判断要不要私有化，看三件事

### 1. 数据敏不敏感（硬指标）

- 数据能不能出内网、能不能给外部看到
- 关键：不是"想不想"，是**法规**说了算
  个人信息保护法、行业监管（医疗、金融尤其严）
- 例子：公开的学生手册 → 不用私有化
  校医院病历 → 必须私有化

### 2. 量稳不稳定

- 先看日均调用量，更要看**峰值**：硬件是按峰值买的，钱是 24 小时在烧
- 量大且稳定 → 私有化划算
- 量小或忽高忽低 → 很不划算，买卡的钱和电费都省不回来

### 3. 要不要定制

- 要不要微调、要不要绑定自己的业务数据和流程
- 只是"能用就行" → 调 API 更省事

## 二、私有化的代价（这条最容易被漏掉）

- **效果有代差**：同样预算买到的卡，跑的多是 7B/14B 开源模型，拼不过旗舰 API 的回答质量
- **要养人**：运维、监控、升级、半夜挂了谁修，都得自己扛
- **升级慢**：模型半年一代，显卡不能半年换一张；API 那边升级是免费的

> 一句话：私有化是"沉没 + 固定"成本，API 是"可变 + 随用随停"。
> 量大且稳定才划算，量小或波动大就亏。

## 三、我优先推荐私有化的场景

数据绝对不能出内网（有合规要求）+ 日常调用量大且稳定。
两个条件缺一个，就得认真算账再决定。

## 附：三个面试问答（速答版）

**Q1 为什么很多企业要私有化部署？**
数据合规是硬约束（不能出内网）；其次是成本——量大且稳定时，
自建比按 token 付费便宜；再次是要微调、要贴合自己的业务。

**Q2 私有化 vs 调 API 怎么取舍？**
看三个维度：数据敏感度、量的规模与稳定性、是否要定制。
代价也要算清：效果代差、运维人力、升级跟不上。

**Q3 一个 5 人团队想私有化部署 70B 给内部 200 人用，你先问什么？**
① 数据敏感到什么程度（不敏感就不用自建）
② 为什么是 70B（7B/14B 够不够——显存是数量级差别）
③ 有没有运维能力、预算多少、峰值并发多少
